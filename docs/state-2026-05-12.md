## TL;DR

Aconteceram **3 incidentes correlatos** entre 9 e 12 de maio:

1. **Falso-positivo** de AMBIENTAL JINGLE em 101 FM (9/5)
2. **Falso-negativo** + **retração indevida** em Oeste Capital (11/5)
3. **Perda total do pgdata** ao tentar deployar o fix do #2 (12/5)

A causa raiz comum dos #1 e #2 (compartilhamento de áudio entre
comerciais) levou a 3 iterações do algoritmo `shared-hash` (F-108
v1→v2→v3). O fix do #3 (camadas de durabilidade) levou a 7 commits
de infra distribuídos em 2 branches.

**Sistema voltou ao ar com base vazia** (recuperação operacional via
recadastro manual). **Camadas de durabilidade implementadas** (bind
mount, R2, snapshot GCP, alerta Prometheus) — esse cenário não pode
repetir.

## Apêndice — comandos úteis de verificação

```bash
# Estado dos containers
docker compose -f infra/docker/docker-compose.yml ps

# Backup mais recente no R2
source infra/docker/.env
docker run --rm \
  -e AWS_ACCESS_KEY_ID="$R2_ACCESS_KEY" \
  -e AWS_SECRET_ACCESS_KEY="$R2_SECRET_KEY" \
  amazon/aws-cli --endpoint-url "$R2_ENDPOINT" \
  s3 ls "s3://$R2_BUCKET/postgres/daily/" | tail -3

# Métricas de backup
curl -s http://localhost:9090/api/v1/query?query=radiocheck_postgres_backup_last_status

# Alerts ativos
curl -s http://localhost:9090/api/v1/alerts | python3 -m json.tool

# Estado do catálogo (depois do recadastro)
docker compose -f infra/docker/docker-compose.yml exec -T postgres \
  psql -U radiocheck -d radiocheck -c "
    SELECT 'clients' tbl, COUNT(*) FROM clients
    UNION ALL SELECT 'stations', COUNT(*) FROM stations
    UNION ALL SELECT 'campaigns', COUNT(*) FROM campaigns
    UNION ALL SELECT 'commercials', COUNT(*) FROM commercials
    UNION ALL SELECT 'detections', COUNT(*) FROM detections;
  "

# Estado do is_shared (após deploy do F-108 v3)
docker compose -f infra/docker/docker-compose.yml exec -T postgres \
  psql -U radiocheck -d radiocheck -c "
    SELECT c.short_id, c.title, c.duration_seconds,
           ROUND(100.0 * COUNT(*) FILTER (WHERE fh.is_shared) / NULLIF(COUNT(*),0), 1) shared_pct
    FROM commercials c JOIN fingerprint_hashes fh ON fh.commercial_id = c.id
    GROUP BY c.id, c.short_id, c.title, c.duration_seconds
    ORDER BY c.title;
  "
```

## Quando você acordar amanhã

Ordem mental:

1. ✅ Sistema está respondendo? `curl https://api.e-monitor.online/v1/internal/health`
2. ✅ Backup rodou na noite? Confere R2 listagem (deve ter ≥ 2 arquivos)
3. ✅ Snapshot GCP rodou? GCP Console → Snapshots
4. Termina o recadastro do catálogo
5. Roda script de migração de volumes (bind mount)
6. Deploya o F-108 v3
7. Olha o Grafana / Prometheus por uma manhã pra ver se nada está
   anômalo

Depois disso fecha PRs das branches em ordem e segue a vida.
